# keepAwake v1.2.0 — agent control (URL scheme, MCP server, Claude Code / Cursor hooks) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** coding agents (Claude Code, Cursor, any MCP client) can keep the Mac awake while they work and let it sleep when they finish. The user sees who is holding it in the menu.

**Architecture:** the running app takes commands through a `keepawake://` URL scheme, and `open -g` launches the app when it isn't running. Agents hold the Mac awake with **holds**: each hold has an id, a display name, an expiry (TTL), and an optional pid to watch. The Mac stays awake while the manual timer is on **or** at least one hold is alive. The app writes its state to a JSON status file, and clients read that file to confirm a command was applied. The single `KeepAwake` executable also runs as a CLI (`hold`, `release`, `start`, `stop`, `status`), a hook handler (`hook`), an MCP stdio server (`mcp`) and an installer (`install` / `uninstall`), the same way it already handles `--snapshot`.

**Tech Stack:** Swift 6, SwiftUI `MenuBarExtra`, `NSApplicationDelegate.application(_:open:)`, `/usr/bin/open`, hand-rolled MCP JSON-RPC over stdio (no SDK), Swift Testing.

**Spec:** chat decisions from 2026-10-25, collected under "Decisions" below. There is no separate spec document. The user asked to skip the questions, so every decision marked *(my call)* is open to change.

## Decisions

- Three layers, built in this order: URL scheme → CLI/hook → MCP → installer + menu. Each layer works without the ones after it.
- **Holds, not on/off.** An agent never turns keepAwake "on" globally. It renews its own hold, and the hold dies on its own: on TTL expiry, when the watched pid exits, on battery guard, or when the user clicks Turn Off.
- **Turn Off in the menu clears every hold** (my call). The user always wins. An agent's next prompt or tool call creates its hold again, which is expected.
- **The manual timer ending does not clear holds** (my call). The two sources are independent.
- Hooks hold for **30 min** and renew on every prompt and every tool call. The hold is released on `Stop` / `SessionEnd` (my call). If the user interrupts with Esc and `Stop` doesn't fire, the Mac sleeps ≤30 min after the last tool call.
- MCP `keep_awake` defaults to **60 min**, allowed range 1…1440. Its hold watches the MCP server's own pid, so it dies with the agent session (my call).
- **Single binary**, no second target in `build.sh` / `project.yml` (my call).
- **Hand-rolled MCP**, no Swift MCP SDK. The repo has zero dependencies and we need 4 methods (my call).
- A command sent while the app is quit **launches the app** (`open -g`) (my call). The menu toggle "Let AI agents keep your Mac awake" (default on) turns agent control off. `uninstall` removes the hooks.
- The installer merges JSON into the user's config files and backs them up once. It never touches a file it can't parse.
- `build.sh` signs **without** the sandbox entitlement, same as the v1.1.0 lid-closed plan. If that plan already changed the `codesign` line, skip that step. The installer UI is hidden in sandboxed (Xcode/App Store) builds. The URL scheme, CLI, hooks and MCP don't need an unsandboxed build.

## Global Constraints

- macOS 14+, Swift 6.0 strict concurrency, no third-party dependencies, universal build through `./build.sh --universal` unchanged.
- URL scheme: `keepawake`. `CFBundleURLName` = `com.michalkrecisz.keepAwake.agent`.
- Status file: `FileManager.default.urls(for: .applicationSupportDirectory, in: .userDomainMask)[0]/keepAwake/status.json`, JSON with ISO-8601 dates, written atomically.
- Limits: `start` minutes 1…43200 (= `maxCustomDays` × 1440) or absent = always. `hold` minutes 1…1440, default 30. Hold id matches `^[A-Za-z0-9._:-]{1,128}$`. Hold name is trimmed and truncated to 40 characters, and defaults to the id.
- Hook ids and names: `claude-code:<session_id>` / "Claude Code", `cursor:<conversation_id>` / "Cursor". MCP ids and names: `mcp:<server pid>` / `reason` ?? `clientInfo.name` ?? "MCP client".
- Hooks never block an agent: they always exit 0. stdout is empty for Claude Code, exactly `{"continue":true}` for Cursor `beforeSubmitPrompt`, exactly `{}` for Cursor `stop`, and empty for everything else. They never wait for the app to confirm.
- Hooks decode only `hook_event_name`, `session_id`, `conversation_id` and `cursor_version`. Prompt text and tool input are never decoded, stored or logged.
- Our hook command string is exactly `"<executable path>" hook --pid $PPID`. An entry is "ours" when its command ends with `/KeepAwake" hook --pid $PPID`.
- Exit codes: 0 ok, 64 usage error, 69 app not responding (`EX_UNAVAILABLE`), 1 installer failure.
- UI copy is in English. The MCP server writes only JSON-RPC lines to stdout; diagnostics go to stderr.
- Tests use Swift Testing in `Tests/KeepAwakeTests`. If `Package.swift` has no test target yet, add `.testTarget(name: "KeepAwakeTests", dependencies: ["KeepAwake"], path: "Tests/KeepAwakeTests")`. Run them with `swift test`.
- Version: `MARKETING_VERSION: 1.2.0`, `CURRENT_PROJECT_VERSION: 3` in `project.yml`. If v1.1.0 hasn't shipped, use the next minor version up from whatever `project.yml` has.

## Review Focus

1. **The agent is interrupted (Esc), so `Stop` never fires:** the hold expires 30 min after the last renewal and the Mac can sleep. Covered by `expiredHoldDropped` (Task 3).
2. **The agent process is killed (crash, `kill -9`, terminal window closed):** the watched pid is dead, so the hold is dropped on the next 1 s tick. Covered by `deadPidHoldDropped` (Task 3).
3. **The user clicks Turn Off while an agent holds the Mac:** every hold is cleared, the assertion is released, and the status file shows `awake: false`. Covered by `turnOffClearsHolds` (Task 3).
4. **The user already has their own hooks or settings in `~/.claude/settings.json` or `~/.cursor/hooks.json`, or the file is malformed:** foreign entries survive install and uninstall, and a malformed file is left byte-for-byte untouched. Covered by `claudeInstallPreservesOtherSettings`, `uninstallRemovesOnlyOurs` and `malformedJsonUntouched` (Task 7).
5. **The app is not running when a hook fires:** the hook still exits 0 in well under 1.5 s (the `SessionEnd` budget), and `open -g` launches the app, which applies the command after launch. Covered by `hookExitsZeroWhenAppMissing` (Task 5) and checked by hand in Task 8.

### Task 6: MCP stdio server

**Files:**
- Create: `Sources/KeepAwake/MCPServer.swift`
- Modify: `Sources/KeepAwake/KeepAwakeApp.swift` (dispatch `mcp`)
- Test: `Tests/KeepAwakeTests/MCPServerTests.swift`

**Interfaces:**
- Consumes: `AgentClient.sendAndConfirm`, `AgentClient.status`, `AgentCommand`.
- Produces:
  ```swift
  final class MCPServer {
      init(client: AgentClient, pid: Int32 = getpid())
      func handle(line: String) -> String?      // one JSON-RPC message in → one response line, nil for notifications
      func run(input: FileHandle = .standardInput, output: FileHandle = .standardOutput)   // until EOF, then releases its hold
  }
  ```
  Protocol rules:
  - `initialize`: reply with the client's `protocolVersion` if it is one of `["2025-11-25", "2025-06-18", "2025-03-26", "2024-11-05"]`, otherwise `"2025-06-18"`. The reply also carries `capabilities: {"tools": {}}`, `serverInfo: {"name": "keepawake", "version": <CFBundleShortVersionString or "dev">}`, and `instructions: "Call keep_awake before long-running work (builds, test suites, model training, large downloads) so the Mac does not fall asleep, and allow_sleep when it is done."`. Remember `clientInfo.name`.
  - `ping` → `{}`.
  - `tools/list` → three tools:
    - `keep_awake`, which takes `{minutes: integer 1–1440, default 60; reason: string, optional}`.
    - `allow_sleep`, which takes `{}`.
    - `keep_awake_status`, which takes `{}`.
  - `tools/call` → `{"content":[{"type":"text","text":…}], "isError": Bool}`.
  - JSON-RPC errors: unknown method with an id → `-32601`; unparseable line → `-32700` with `"id": null`. A message with no `id` is a notification, and the server sends no response.
  - `keep_awake` holds as `mcp:<pid>` with the name from Global Constraints, then confirms it with `until: { $0.holds.contains { $0.id == id } }`. On success the text is `Keeping the Mac awake until 15:42. Call allow_sleep when the work is done.` On failure it sets `isError: true` with the text `keepAwake did not respond. Make sure keepAwake.app is installed and "Let AI agents keep your Mac awake" is on in its menu.`

- [ ] **Step 1: Write the failing tests** (using a fake client as in Task 4):
